## Implemented Slices

- Email recipient list/count excludes soft-deleted owners; client templates exclude server secrets and host/environment template functions.
- Renewal/reset orders store a stable subscription ID; fulfillment prefers it without token fallback when an ID exists, and checks subscription ownership/plan.
- Subscription tokens use cryptographic randomness; commissions use bounded integer arithmetic.
- Subscription delivery rejects held subscriptions and disabled/deleted owners, tolerates deleted plans, and handles pre-1971 unlimited expiration across timezone offsets.
- JWT parsing enforces HS256, expiration and validated session claim types. Authentication rejects invalid account state without logging the bearer token.
- Shared Redis session epochs, password-attempt reservations, one-use codes, password CAS updates, session revocation and logout are wired into local authentication flows.
- Credential changes and identity replacements require current-identity proof and revoke sessions. Guest session exchange checks payment time and revocation epoch.
- OAuth states are scoped to login/bind and account, consumed once, and browser redirects are pinned to configured site origin. Telegram replay protection fails closed on Redis errors.
- Argon2 hashing and verification share a four-operation concurrency limit; salt/hash length and parameter bounds are checked.
- SMTP verifies certificates by default, supports explicit implicit TLS and certificate opt-out, requires STARTTLS for SSL on submission ports, bounds dialing/delivery and supports cancellation.
- Email verification payload validation avoids type-assertion panics; SMTP delivery uses the task context.
- Subscription sweeps recheck eligibility and notify only changed rows. Shared owner-token task locks support heartbeat and conditional release. Calendar traffic resets use persisted cycle markers and catch up missed runs without mass-resetting unmarked historical subscriptions.
- MySQL migration DSNs escape credentials; PostgreSQL query values are decoded once and default to Asia/Shanghai unless explicitly configured.
- Payment callbacks bind trade numbers under an order row lock, verify immutable amount/currency snapshots and audit mismatches. Debug mode cannot bypass EPay or Cryptomus signatures. Cryptomus received-fund review states are audited.
- Checkout and close share an owner-token lock. Checkout persists payment expectations and hosted sessions. Callbacks use configured site/payment origins, never request Host. EPay sends exact minor units; Alipay uses a fixed expiry.
- Stripe clients use instance credentials, idempotent Checkout creation, currency unit conversion, async success handling, cancel/expire and receipt lookup. Webhook rotation preserves omitted secrets, records endpoint IDs and cleans up on failed persistence; behavior-level rotation tests remain pending.
- Gateway-aware close reconciles collected payments before releasing gift credit or stock; conditional close and atomic inventory increments prevent repeated release. Unconfirmed automatic expiration retries instead of silently succeeding.
- Activation fulfillment, coupon accounting, commission and final status share one order-lock transaction. Notifications and cache invalidation run after commit. Replayed recharge and commission tasks, failed settlement rollback, and paid orders targeting canceled subscriptions have focused regressions.
- Refunds enforce ownership, lock and conditionally cancel the latest subscription, refund gift credit first, count only paid renewals, and reverse proportional commission from the recorded recipient. Refund calculation uses total paid value and current reset cycles, preserving unlimited traffic and no-expiry sentinels.
- Renewal, reset, token rotation, notes, admin status/settings and redemption writes are column scoped. Trial and rotated node credentials use random UUIDv4; trial subscriptions inherit unlimited traffic and node groups.
- EPay V1/V2 page and API checkout, configured-version callback verification, signed V2 query/close, exact amounts and durable API-create attempts are wired. HTTP protocol and cross-request checkout regressions pass. V2 close races, relative API paths and real gateway integration still need business-level validation.

- Admin orders start pending, validate type/quantity/trade number, bind renewal/reset targets by stable ID, and reserve inventory/coupon usage in the creation transaction. Buyer and guest creation use atomic inventory/coupon reservations. Close/refund release reservations once; activation does not recount reserved coupons. Rollback and replay regressions pass.
- Guest coupon limits use durable order identity. A paid guest order whose identity already has an account is refunded to that account and closed atomically. V2 anonymous idempotent replays are limited by key and IP before fingerprint comparison; concurrent-create recovery performs the same ownership checks.
- Batch email campaigns run inside the queue context, persist cursor and daily quota counters, stop before the task deadline, and enqueue six-hour continuations with deterministic chunk IDs. ### Migrations

- `02162` **down** re-added the global unique key on `auth_identifier` unconditionally. The `up` deliberately permits one identifier under different auth types, so the first such row made the rollback fail and left the version dirty, **blocking every later migration**. Both engines now neutralise cross-type duplicates first (rename, keeping the lowest `id`, deterministic and idempotent) and guard the DDL. The known one-way `verified` backfill is documented, not silently ignored.
- `02169` `CREATE TABLE traffic_batch` lacked `IF NOT EXISTS` in both engines (this fork's own `0541438e` added the same guard to MySQL 02160 for this exact failure). Guarded.
- PostgreSQL was **missing 02150** entirely: MySQL widened `user.password` to `varchar(255)` but PostgreSQL stayed at `varchar(100)`, and the fork's argon2id PHC hash measures **97 characters** — three characters of headroom. Both engines now have 02150 up/down and the version sets are identical.
- Postgres `02160` was unguarded while its MySQL twin was guarded; confirmed and guarded.

### Audit findings refuted

- **Order close vs. concurrent checkout** was reported as a race. It is not: `CloseOrder` and `PurchaseCheckout` both hold the same Redis lock `order-checkout:<orderNo>` for their whole duration (fail-closed via `KeepAlive` → `cancel`). Verified by reading both call sites and by mutation-testing the two lock keys, which makes the new tests fail. No production change; the tests are kept.
- **`c45df9e2` (traffic chunking + node cache fence)** is genuinely not ported, and the ledger already said `Pending` — accurate. Row-by-row application means the placeholder-limit bug cannot occur here, but plan edits do not clear the servers' `server:user:*` caches. Recorded as a known gap, not silently claimed.
- **`A2` (traffic report contention)** and **`A3` (report marker TTL)** are real hardening observations, not correctness bugs; recorded under "Still open".
- **Schema/index drift** (e.g. `subscription_period` declares no `Indexes()` while 02168 creates two) is DDL-only drift: no query references those index names and ent auto-migration never runs, so it is inert. Same class as defect 1 but without a runtime consequence.
